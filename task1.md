# Анализ моделей и инфраструктуры для RAG-бота

## 1. Сравнение LLM-моделей

### Локальные модели (Hugging Face / Ollama)

| Критерий | Локальные (Llama 3.1, Mistral, Qwen) |
|----------|--------------------------------------|
| **Качество ответов** | Хорошее для своих размеров, но уступает GPT-4o/Claude 4 на сложных задачах (88.7% MMLU против ~92% у топовых облачных) |
| **Скорость работы** | Зависит от железа: 7B модель = ~30 токенов/сек на RTX 3090, 70B модель = ~8 токенов/сек на A100 |
| **Стоимость** | Разовая затрата на GPU: RTX 3090 ~$1500, A100 ~$15000. Без API-платы за токены |
| **Развёртывание** | Среднее: Ollama упрощает, но требует настройки GPU/V-RAM |

### Облачные модели (OpenAI / YandexGPT)

| Критерий | OpenAI GPT-4o / Claude 4 | YandexGPT |
|----------|--------------------------|-----------|
| **Качество ответов** | Топовые (88-92% MMLU, лучшие reasoning capabilities) | Хорошее, но уступает OpenAI (~80-85% MMLU) |
| **Скорость работы** | Высокая (100+ токенов/сек), зависит от API лимитов | Высокая, но может быть задержка в пиковые нагрузки |
| **Стоимость** | $15-25/1M токенов (вход), $2.50/1M токенов (выход) — break-even ~1M токенов/месяц | По запросу Yandex Cloud |
| **Развёртывание** | Простое: API ключ = 10 минут настройки | Простое через Yandex Cloud |

**Итог**: Локальные — приватность + отсутствие зависимости от внешних API; Облачные — качество + простота.

## 2. Сравнение моделей эмбеддингов

### Скорость индексации

- **Sentence-Transformers (BGE, e5)**: CPU-only ~1000 предложений/сек на современном CPU, GPU ускоряет в 5-10x
- **OpenAI text-embedding-3-small**: API вызовы ~3000 embeddings/мин, но зависит от network latency

### Качество поиска (MTEB leaderboard)

| Модель                           | MTEB Score | Размер |
|----------------------------------|------------|--------|
| **BGE-en-ebedding-large**        | 64.4       | 1024   |
| **e5-large-v2**                 | 63.5       | 1024   |
| **sentence-transformers/all-MiniLM-L6-v2** | 56.2 | 384   |
| **OpenAI text-embedding-3-small** | 62.3      | 1536   |

### Стоимость

- **Локальные**: Бесплатно после загрузки модели (~$0)
- **OpenAI**: $0.0001 / 1K токенов ~ $0.10/1M токенов

**Итог**: Локальные (BGE) — бесплатно + контроль; OpenAI — качественно + простота.

## 3. Сравнение ChromaDB vs FAISS

### Скорость

- **FAISS**: Быстрее на больших датасетах (10M+ векторов), использует GPU indexing; 1000x быстрее в benchmark
- **ChromaDB**: ~50ms запрос на 10K векторов, простая интеграция

### Внедрение и поддержка

| Критерий           | ChromaDB                                    | FAISS                              |
|--------------------|---------------------------------------------|------------------------------------|
| **Сложность внедрения** | Низкая (Python-only, install + 10 строк кода) | Средняя (C++ bindings, требует понимание индексов) |
| **Удобство работы** | Высокое: Python API, встроенный query language | Низкое: Ручной выбор индекса, документация сложнее |
| **Персистентность** | Встроенная (SQLite back-end)                | Требует ручную реализацию         |
| **Стоимость инфраструктуры** | Только RAM                               | Только RAM                        |

**Итог**: ChromaDB — для RAG с документами, FAISS — для high-performance batch processing.

## 4. Рекомендуемая конфигурация сервера

| Вариант | CPU | RAM | GPU | Стоимость сервера | Среда применения |
|---------|-----|-----|-----|-------------------|------------------|
| **Базовый** | 8 ядер (Intel i7/Ryzen 7) | 32GB | RTX 3060 12GB | ~$1500 | Тестирование, до 100K документов |
| **Средний** | 16 ядер (Ryzen 9/i9) | 64GB | RTX 4090 24GB | ~$3500 | Production, до 500K документов |
| **Продвинутый** | 32 ядра (AMD EPYC/Xeon) | 128GB | A100 40GB (или 2x A6000) | ~$15000+ | High load, миллионы документов |
| **Облачный** | 8 vCPU | 32GB | T4/A10G (AWS/GCP) | ~$200-500/мес | Elastic load, без капитальных затрат |

### Требования по RAM для моделей

- **7B модель**: ~14GB VRAM (FP16), 8GB (quantized Q4)
- **13B модель**: ~26GB VRAM (FP16), 12GB (quantized Q4)
- **70B модель**: ~140GB VRAM (FP16), 40GB (Q4) — требует 2x A100

## 5. Итоговые рекомендации (3-4 варианта)

### Вариант 1: Полностью облачный (Рекомендуемый для старта)

- **LLM**: OpenAI GPT-4o
- **Эмбеддинги**: OpenAI text-embedding-3-small
- **Векторная БД**: ChromaDB (локально)
- **Сервер**: Минимальный (8GB RAM, любой CPU) — только для ChromaDB
- **Стоимость**: ~$50-200/месяц (API) + $20 (сервер)
- **Плюсы**: Максимальное качество, минимум настройки, масштабируемость
- **Минусы**: Зависимость от внешнего API, данные уходят в облако

### Вариант 2: Гибридный (Приватность + качество)

- **LLM**: OpenAI GPT-4o
- **Эмбеддинги**: BGE-large (локально)
- **Векторная БД**: ChromaDB
- **Сервер**: Средний (RTX 3060)
- **Стоимость**: ~$1500 (разово) + $50/месяц (API)
- **Плюсы**: Документы не уходят в облако, эмбеддинги локально, качество LLM
- **Минусы**: Требуется GPU для эмбеддингов

### Вариант 3: Полностью локальный

- **LLM**: Llama 3.1 70B (или Qwen 2.5 72B)
- **Эмбеддинги**: BGE-large (локально)
- **Векторная БД**: ChromaDB
- **Сервер**: Продвинутый (2x A100 или аренда в Genspark/RunPod)
- **Стоимость**: ~$2000-5000 в месяц (аренда при облачном GPU) или $15000+ единоразово (свой сервер)
- **Плюсы**: Полный контроль данных, отсутствие API зависимости
- **Минусы**: Качество LLM ниже GPT-4, сложность поддержки, дорого для high load

### Вариант 4: Российские облака (При наличии требований к локализации)

- **LLM**: YandexGPT API
- **Эмбеддинги**: ruBERT или аналоги
- **Векторная БД**: ChromaDB или PostgreSQL + pgvector
- **Сервер**: Любой в Yandex Cloud/Vk Cloud/Cloud
- **Стоимость**: По запросу
- **Плюсы**: Соответствие российским требованиям, русский язык
- **Минусы**: Меньше документации, качество ниже OpenAI

## Выбор лучшего варианта

**Для типичного корпоративного RAG-бота рекомендуется Вариант 1 (Полностью облачный)**:

1. **Качество**: GPT-4o обеспечивает лучшие ответы для бизнес-задач
2. **Стоимость**: Прозрачная, предсказуемая ($50-200/месяц)
3. **Скорость**: 100+ токенов/сек vs 8-30 токенов/сек локально
4. **Простота**: 10 минут настройки vs дни настройки локального GPU

**Если требование — конфиденциальность документов**, тогда Вариант 2 (Гибридный): эмбеддинги локально, LLM в облако.

**Если данные строго конфиденциальны и нельзя отправлять даже в OpenAI** — Вариант 3, но нужен бюджет на мощный GPU-сервер.

---

## Заключение

Для RAG-бота с документами рекомендуемая конфигурация:

- **Векторная БД**: **ChromaDB** — простая интеграция, встроенная персистентность, отлично подходит для RAG pipeline
- **Эмбеддинги**: **BGE-large** (локально) или **OpenAI text-embedding-3-small**
- **LLM**: **OpenAI GPT-4o** — оптимальный баланс качества и стоимости
- **Сервер**: Минимальный с ChromaDB + API для LLM

ChromaDB выбрана за: простоту, встроенный SQLite, отсутствие сложной настройки, Python-first подход, отлично работает с RAG-пайплайнами.
